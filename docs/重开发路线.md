# AI Enterprise Workspace 重开发基线

日期：2026-09-14。产品范围以根目录《AI Enterprise Workspace 项目描述.md》为准；本文件定义实现顺序与验收条件。旧《项目描述.md》及旧版《开发文档.md》中的冲突范围不再作为开发依据。原始描述作为需求资料保留，不作为自动执行命令。

## 产品范围

面向企业办公的预置数字员工工作空间。用户通过 AI Assistant 或指定专业员工提出目标，系统交付可追溯的文档、报告和任务。GUI 采用侧栏、总览、桌面应用入口、独立工作详情，使用用户提供的 application icon.png。

角色固定为 AI 管家、数据分析师、文档专家、会议秘书、HR 助手、CRM 助手、企业知识专家、产品设计师、AI 开发工程师。业务能力按阶段接入；可生成文本方案不等于已经能访问文件、执行统计、管理客户或发送消息。

## 多智能体机制

统一入口 -> Supervisor 规划或指定员工流程 -> 结构化 DAG 校验 -> 限流并行 Worker -> 汇总交付 -> 审核 -> 修订或人工处理 -> 归档。

Supervisor 只能选择预置 employee_id，节点数有上限。拒绝未知员工、重复 ID、保留 ID、缺失依赖与循环。规划失败使用预置流程并记录回退事件。

使用锁定的 CrewAI 0.86 `Agent + Task + Crew.kickoff()` API。每个节点传入专业职责、目标、证据和显式依赖的真实成果。Python 管理 DAG，CrewAI 管理专业角色推理；不是 CrewAI hierarchical delegation，也不宣称已经迁到复杂 Flow 状态机。

| 模式 | 本阶段范围 |
| --- | --- |
| Sequential | 依赖结果就绪后执行后继节点 |
| Parallel | 独立节点最多同时执行 2 个 |
| Conditional | 按员工、业务意图、模型配置和审核决定执行路径 |
| Feedback Loop | 真实审核；REVISE 触发一次修订和复核 |
| Human-in-the-loop | 复核不通过可由用户接受交付并归档，或取消 |
| 外部写入 | 无连接器时阻断确认，不能将发送/删除标记成功 |

无模型配置明确失败，不使用模板伪装成功。取消阻止后续节点；已发往模型的单次请求可能继续消耗额度。当前副作用关键词检测仅用于没有写工具的本地阶段，不能替代正式工具权限检查。

## 目标架构

已由用户确认：Java 21 + Spring Boot 3 / Spring Cloud Gateway。R2 根据官方兼容表锁定 Boot 3.5.16 / Cloud 2025.0.3。

```text
React Workspace
  -> Spring Cloud Gateway (认证、路由、限流)
  -> Spring Boot Workspace Service (业务、权限、任务、文档、报告)
      -> MySQL (业务事实、版本、审计)
      -> Redis (缓存、幂等锁、短期状态)
      -> MinIO (原文件、解析物、报告导出)
      -> RabbitMQ (任务命令、事件、重试、死信)
      -> Python CrewAI Agent Runtime
          -> LLM Provider
          -> Elasticsearch (分块、dense_vector、检索)
          -> 受控 MCP/业务工具
```

R2 已将业务 API 和持久化迁入 Java/MySQL，Redis 管理会话和认证限流；Python 只保留内部执行与知识服务。SQLite 作为历史备份，MinIO 留待 R3。内部执行合约包括 claim、heartbeat、plan、events 与结果 save，使用 lease token 拦截过期 Worker。

模型由 deploy/.env 提供，支持已确认的 qwen3.7-flash、kimi-k3、qwen3.8-27b。前端只能查看模型名。Embedding 延用环境配置；改维度需新索引、重建及检索验证。

## 业务数据设计

所有业务记录归属 workspace_id。R2 已从服务端认证确定租户，不信任浏览器自由传入的参数。

| 聚合 | 实体/表 | 关键约束 |
| --- | --- | --- |
| 身份 | workspaces、users、memberships、roles、permissions | 成员角色按空间绑定 |
| 员工 | employee_profiles、employee_versions、tool_grants | 固定 ID、配置版本、工具白名单 |
| 工作 | tasks、task_nodes、task_events、task_attempts | 员工、来源、状态版本、claim token、事件序号 |
| 会话 | conversations、messages | 人/AI/系统消息、task_id |
| 文档 | documents、document_versions、index_jobs | MinIO 对象键、分类、校验和、处理状态 |
| 会议 | meetings、transcripts、action_items | 原文位置、负责人、期限、幂等任务链接 |
| 分析 | datasets、analysis_runs、charts | 数据版本、统计方法、执行日志 |
| 报告 | reports、report_versions、report_sources | 来源任务、审批、引用与版本 |
| 审计 | approvals、audit_logs、outbox | 参数快照、审批者、过期时间、发送幂等键 |

R1 增加 tasks.employee_id 与 reports 表及原子 claim；R2 已增加 MySQL 行锁、120 秒执行租约、20 秒续约、失效回收和最多 3 次租约尝试，并完成旧库备份、计数与逐任务比对。

## 14 周路线

| 阶段 | 周次 | 交付 | 验收条件 |
| --- | --- | --- | --- |
| R1 核心重建 | 1–2 | React、真实文本员工、任务事件、报告 | 新目标产生实际模型成果；交接可追踪；无配置不伪成功；刷新成果仍存在；错误可见 |
| R2 企业基础 | 3–4 | Java 21、Spring Boot 3、Spring Cloud Gateway、MySQL、Redis、认证 | 两租户隔离；JWT/RBAC；旧数据计数匹配；队列幂等与失败恢复 |
| R3 文档与知识 | 5–6 | MinIO、PDF/Word/Excel 解析、文档中心、入库 | 上传->预览->索引->带来源问答；失败重试；更新无旧片段；引用无越权 |
| R4 会议与任务 | 7–8 | 记录、秘书、行动项、任务联动 | 根据 transcript 提取；缺失期限留空；重复提取不重复建任务 |
| R5 分析与报告 | 9–10 | CSV/Excel 计算、图表、HR/CRM | 样例总计/趋势与人工一致；无凭空数字；报告版本和来源可追踪 |
| R6 工具协作 | 11–12 | MCP、通讯模拟连接器、审批 | 草稿->参数预览->确认->幂等写入->回执；参数改变重批；超时/死信恢复 |
| R7 产品验收 | 13–14 | 审计、压测、恢复、Demo | 三条主场景；延迟/成本数据；Docker 新环境部署；备份恢复 |

MVP = R1；可用企业产品 = R2–R5 并通过权限/恢复验收；高阶协作 = R6–R7。周次为估算；目录存在不等于完成，本阶段也不等于整份目标完成。

## 安全与质量

- 密钥仅环境注入，不进入前端、日志、响应、Git。
- 检索片段与上传资料作为数据，不授予工具权限。
- 当前无代码执行或外部写工具；修正历史“确认即成功”语义。
- 正式工具校验用户、租户、动作、资源、审批快照和幂等键。
- 文件限制大小/类型，隔离解析；下载与 RAG 都需授权。
- Markdown 不渲染原始 HTML；执行错误不回显供应商原始响应。
- R2 已验证身份与服务认证、跨空间访问、取消结果保护、执行租约和 SSE 游标。公网 HTTPS、密钥轮换、SSO、备份恢复压测仍待验收，当前用于本地开发。
