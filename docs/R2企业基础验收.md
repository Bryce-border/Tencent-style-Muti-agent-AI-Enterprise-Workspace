# R2 企业基础：实现与验收

日期：2026-09-14。对应《重开发路线》R2。R3 文件管理、MinIO 和文档解析仍未进入本阶段。

## 运行架构

```text
React / Nginx :8080（或 Vite :5173）
  -> Spring Cloud Gateway :8090
  -> Java Workspace Service :8081
      -> MySQL 8.4：身份、成员、任务快照、事件、报告、Outbox、审计
      -> Redis 7.4：JWT 会话登记、撤销和认证请求限流
      -> RabbitMQ：持久化任务命令
      -> Python API：员工目录、模型状态、受控知识检索/文本入库
  Python Worker -> Java 内部执行 API：claim / heartbeat / plan / event / save
  Python Worker -> CrewAI / LLM / Elasticsearch
```

Java 21、Spring Boot 3.5.16、Spring Cloud 2025.0.3。版本根据 Spring 官方兼容表中的 Boot 3.5.x / Cloud 2025.0.x 对应关系选择；依赖在 Maven POM 锁定。开发编译使用本机 `D:/intellij/IntelliJ IDEA 2025.3.4/jbr` 的 Java 21.0.10；容器使用 Temurin 21 JRE。未修改系统默认 Java 8。

Java 是业务写入的唯一所有者。Python 的 `RemoteTaskStore` 通过内部服务 API 读写任务，不直接连接 MySQL，不再在运行中的 SQLite 中新增业务数据。原 `TaskStore` 保留用于 R1 单元测试与旧数据迁移。

## 登录与权限

- 注册新账户时创建独立工作空间，注册者为 ADMIN。首次启动且用户表为空时，使用环境变量中的管理员账户创建 `default` 空间。
- JWT 签名使用环境密钥，8 小时有效，通过 HttpOnly、SameSite=Lax Cookie 传输，不放 localStorage。Redis 保存会话 ID，注销和切换空间撤销旧会话。
- 每次请求从 JWT 的用户与空间查询当前成员资格和角色；变更角色无需等待 JWT 到期。
- ADMIN 可管理成员与查看审计；MEMBER 可提交、取消、审核交付和写入知识文本；VIEWER 只读。成员管理目前添加已注册用户，并可调整角色；移除成员、找回密码和 SSO 留待后续。
- 工作空间从服务端身份确定，忽略公开 API 请求里的 `workspace_id`。详情、事件、SSE、导出、报告、消息和知识检索均使用空间范围。越权访问任务/报告返回 404。
- 外部变更请求要求 `X-Workspace-Request: 1`，浏览器 Origin 必须在部署白名单中；不开放跨域 CORS。生产 HTTPS 部署必须设置 `COOKIE_SECURE=true` 并配置正确域名。
- 内部 API 使用独立环境密钥 `X-Internal-Token`，网关剥离内部身份头且不路由 `/internal`；Nginx 对该路径返回 404。Python 在 R2 模式下只接受带服务密钥的目录/检索接口请求。
- 端口绑定本机回环地址。Elasticsearch 与 RabbitMQ 沿用本地开发配置，不视为已完成公网生产加固；不要直接把内部服务端口发布到公网。

## 任务一致性与恢复

1. 创建任务与 Outbox 在同一 MySQL 事务提交。支持 `Idempotency-Key`；相同空间、相同键与参数返回同一任务，参数改变返回 409。
2. 分发器等待 RabbitMQ publisher confirm，失败时保留 Outbox；PENDING 命令每 30 秒可重发，消费者原子 claim 拦截重复执行。
3. claim 在行锁下写入随机执行租约，期限 120 秒；Python 每 20 秒续租。保存结果、更新计划和事件均受租约约束。
4. 租约失效后重置为 PENDING 并重投，新的 lease token 拦截旧 Worker 的迟到结果。连续 3 次执行租约失效则明确 FAILED。
5. 取消与确认使用行锁；取消后的结果不能覆盖状态或归档。报告在真实成功交付/人工接受时写入，task_id 唯一。
6. SSE 事件携带数据库事件 ID，支持 `Last-Event-ID` 续传；页面保留轮询兜底。异步请求分派的授权已单独测试。

本机制提供至少一次投递与有界重试，不宣称分布式 exactly-once。已经发送的模型请求可能仍消耗费用。未接入写工具，未来外部副作用还需工具级幂等键、审批参数快照和回执。

## 构建与启动

从项目根目录执行（PowerShell 7、Node/npm、Maven、JDK 21、Docker Desktop）：

```powershell
./deploy/build-r2.ps1 -JdkHome 'D:/intellij/IntelliJ IDEA 2025.3.4/jbr'
docker compose --env-file deploy/.env.r2 -f deploy/docker-compose.yml -f deploy/docker-compose.r2.yml up -d --build
```

`build-r2.ps1` 先执行 Java 测试/打包和 React 生产构建，Dockerfile 使用生成的 JAR 与 dist。新环境需先构建产物；不能只执行 Compose 就跳过编译。npm 和 Maven 缓存位于项目 `.tools`。脚本不会覆盖已有 `.env` 或 `.env.r2`。

访问 `http://localhost:8080`。本地 Vite `http://localhost:5173` 同样通过 Java 网关联调。默认管理员用户名为 `admin`，随机密码见本地 `deploy/.env.r2` 的 `BOOTSTRAP_PASSWORD`；不会在 Git、页面或日志中输出真实凭据。用户也可直接注册自己的独立空间。

## 剩余边界

R2 是本地可运行的企业基础，不代表生产上线。后续需完成密码重置/SSO、成员删除、正式 HTTPS、服务密钥轮换、细粒度资源授权、登录请求按可信入口地址限流、备份恢复演练与压测。当前网关使用固定服务地址；没有引入注册中心或多副本部署。

R3 下一步：MinIO 对象存储、文件上传/版本、PDF/Word/Excel 解析、索引更新与删除、文档级权限和带引用问答评测。现有知识接口仍为文本入库，不宣称已支持附件解析。
