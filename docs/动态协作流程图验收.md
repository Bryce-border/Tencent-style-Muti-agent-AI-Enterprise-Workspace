# 动态协作流程图

日期：2026-09-14。本阶段将工作详情原有员工列表升级为根据真实执行事件更新的可交互流程图。无需修改数据库结构；桌面客户端与 Web 共用该页面。

## 用户操作

1. 从 AI Assistant 提交工作，或从任务中心打开已有任务。
2. 在“动态协作流程”中查看当前进度；尚未生成计划时只展示已知阶段，计划返回后展开专业员工。
3. 点击任一节点打开详情，查看完整名称、负责角色、节点标识、目标、时间、输入依赖、前置成果、输出与异常。运行中耗时持续更新；没有起止记录的旧节点不伪造耗时。
4. 使用“定位当前节点”、横向滚动、缩放、“查看全图”和展开画布浏览较长流程；展开后按 Esc 收起。节点支持键盘访问，关闭详情恢复节点焦点。
5. 存在自动重试时，可在执行轮次下拉框查看历史；默认跟随最新轮次。旧轮次的完成事件不会把新轮次节点提前标记成功。

## 节点与协调方式

| 节点 | 含义与详情 |
| --- | --- |
| 接收工作目标 | 用户原始请求 |
| 任务执行器 · 领取任务与模型准备 | 开始本轮执行，显示非敏感模型名称/配置来源 |
| AI 管家 · 目标拆解与协作规划 | Supervisor 计划、员工目标与依赖；规划回退有明确提示 |
| 任务调度 · 指定员工与依赖编排 | 用户直接指定员工时的编排方式 |
| 企业知识库 · 检索与证据准备 | 搜索、命中数量、跳过或检索异常；候选不自动等于引用 |
| 专业员工 · 具体目标 | 使用中文角色和本次计划目标命名；展示真实节点成果与前置输入 |
| 文档专家 · 汇总最终交付 | 合并依赖节点成果；单文档员工无额外汇总时不虚构该节点 |
| AI 管家 · 初稿质量审核 | 初审意见与通过/修订决定 |
| 文档专家 · 按审核意见修订 | 仅收到修订反馈后展开，包含意见、修订稿与异常 |
| AI 管家 · 修订稿复核 | 单独记录复核开始、结果与异常 |
| 人工审核 · 确认或取消交付 | 自动审核未完成或未通过时显示；接受动作仍由用户执行 |
| 人工处理 · 外部连接器未配置 | 显示阻断原因，不假装外部操作已完成 |
| 工作空间 · 交付与报告归档 | 只有实际 CrewAI 成果成功后提供报告入口；取消/失败不归档 |

依赖关系按拓扑顺序布局，独立节点放在同列不同行，以箭头连接分支与汇合。运行节点高亮并显示流动连线；系统减少动态效果偏好下关闭连线动画。审核修订以“初审 → 修订 → 复核”的独立节点呈现，并标明边的触发条件。

## 实现边界

- `apps/workspace/src/workflow-model.ts` 将事件与任务快照投影为状态图，隔离执行轮次，并兼容乱序依赖。
- `workflow.tsx` 使用 HTML 按钮与 SVG 连线，沿用已有 SSE 通知和 3 秒轮询，不额外安装图编辑器依赖。
- `workflow.css` 延续玻璃质感风格；窄屏详情移到画布下方。画布自身滚动，避免撑宽整个页面。
- Python 新增 `knowledge.started`、`revision.started`、`revision.completed`，审核事件带 `round`，异常带 `stage`。未改变 CrewAI 版本或引入新的工具权限。
- 节点详情只展示业务输入、成果与允许字段，不读取密钥，不展示模型内部思维链。
- 老任务可能缺少修订/复核独立事件；这类节点标记“未记录”并说明限制，不能从最终成功推断每一步都执行成功。
- 这是执行观察界面，不是拖拽修改计划、重放某个节点或调整业务执行顺序的编辑器。

上述真实联调验收的是执行可视化与事件真实性，不代表回答质量全部达标：汇总仍输出了用户未要求的处理说明，模型审核只检查了两条建议的字数，未拦截全部额外文字。格式硬校验属于后续质量改进，流程图准确展示当前审核结果，不自行改写审核结论。修订/复核、重试历史分支通过状态测试和受控运行时测试验证，本次成功任务没有触发这些分支。
