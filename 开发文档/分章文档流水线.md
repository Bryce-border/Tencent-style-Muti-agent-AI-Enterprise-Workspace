# 分章文档流水线（2026-09-18）

本轮按《项目优化方案》第 11–14、17–18 项推进，聚焦长文档、共享上下文、审核修订、成果与恢复。SQLBot 暂缓。

## 已实现

用户描述目标 → 模型生成预计输出 → 用户修改并批准目录 → 共享文档记忆 → 顺序生成各章 → 全文一致性审核 → 必要时定向修订 → 复核 → 组装 Markdown → 自动通过或人工确认。

- 预计输出新增 `generation_mode`，支持 `single` 与 `chapters`；Java/Python 都校验枚举值和目录长度。普通任务继续使用现有 DAG 执行器。
- 共享记忆采用结构化事实、术语、约束、未知项；章节结果包含完整正文及摘要。后章读取前文摘要，审核读取全部正文。
- CrewAI 0.86 的 Agent/Task/Crew 负责实际生成和结构化输出，应用执行器负责依赖、时限、取消、事件与租约。没有依赖未安装的新版本 API。
- 最多 10 章；自动修订最多 3 章、1 轮，随后复核。审核失败或问题过多时保留正文并要求人工处理，不伪造自动通过。
- 最终组装由代码按目录拼接完整正文，不再调用模型做全文摘要。引用仍按最终正文中的实际来源标记筛选。
- 会话进度逐章显示；成果区提供可折叠章节和共享记忆；流程图增加章节修订与组装节点，节点可查看结果和事件。
- 本轮记录 Agent 调用次数、失败/中断、耗时、复用章节数及供应商回报 Token。未回报不等同零消耗，没有配置模型单价时不估算费用。

## 检查点与隔离

每章完成后将 `document.checkpoint` 保存为任务事件。检查点绑定任务 ID、批准方案、有效历史/个人记忆、检索证据及模型参数；上下文变化时重新生成，避免误用旧内容。

Java 只向持有该任务有效租约的执行器提供检查点。重试端点经过成员写权限和私人任务可见性检查，要求当前会话批准的失败分章任务、会话未归档且没有其他活动任务。重复重试请求保持幂等；新方案产生后不允许续作旧任务。

章节草稿不直接归档，只有审核通过或用户接受交付才进入报告。重试期间 GUI 不展示上一轮的旧成功状态或旧结果。用户明确要求“仅使用本次资料”时跳过历史、个人记忆和检索；并保留显式查询公司制度的正常检索行为。

### 限制

这是有限章节的文档流水线，不保证任意长度或严格字数。建议每章 300–800 字，单次输出受模型 Token 上限约束。默认每轮执行总时限 1200 秒，单调用等待上限 100 秒。取消不调度后续章节，但不能撤回已经发给供应商的请求。

共享事实来自模型整理，仍须审核，不能代替权威证据。失败调用不保证供应商回报 Token；指标不包括预览规划、既往轮次及未回报用量。事件保存完整章节，后续需做保留周期和存储容量治理。

本轮不宣称整个优化方案完成。后续重点为：记忆相关性召回与重要度管理、用户模板中心、固定业务评测集与模型对比、知识片段导航；SQLBot 按用户要求后置。SSE 逐字输出、PDF/Word/PPT 导出和真实外部系统写入仍未实现。

## 演示步骤

1. 启动根目录 `启动工作空间.ps1`，或打开 `http://localhost:8080`。
2. 新建会话，输入一个包含已知事实、角色和约束的多章节文档目标。
3. 修改预计输出，选择“逐章生成”，设置目录并确认执行。
4. 打开执行过程，查看共享记忆、逐章生成、审核/修订、组装节点及调用统计。
5. 在产出结果展开每章和共享事实，下载 Markdown；人工待确认时先检查再接受。
6. 若章节生成失败，点击“重试并复用已完成章节”，观察新轮次的复用标记。

完整启动和升级命令见根目录 README。
